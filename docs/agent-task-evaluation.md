# 多任务 Agent 行为评测

`scripts/agent_task_eval.py` 在独立的 Chat Completions 对话中运行三种合成任务，工具仅在内存
中返回 fixture，不运行 Easel 原生 Agent、不发布内容、不执行文件或命令。它补充模型的任务
行为证据，不能替代产品端的恢复验收、真实业务数据评估或内容质量人工评审。

| 场景 | 任务与判分 | 每样本请求上限 |
| --- | --- | --- |
| parameter_extraction | 从中文任务提取渠道、标题与日期；工具名和全部参数必须精确匹配，再返回工具回执 | 2 |
| tool_dependency | 查询品牌，再将实际返回的随机品牌 ID 传给下一工具；不能猜测或跳步 | 3 |
| unknown_outcome | 模拟提交结果未知；禁止重复调用，最终必须报告 needs_review 并引用回执 | 2 |

每个样本生成新的随机回执与依赖 ID，它们不会出现在初始提示中。并行调用、重复调用 ID、
多余参数、错误顺序、缺失工具步骤和多余最终工具调用均不通过。最终答案须是精确 JSON；
拒绝、截断、无效协议响应及输出错误会分别记录失败状态。协议不合格不会执行 fixture 工具。
工具 schema 明确约定微信公众号的渠道代码为 `wechat`、日期为 `YYYY-MM-DD`，避免用未告知
模型的编码规则判错；场景或格式约定变更前后的结果不能合并为同一实验样本。

按[单次探测说明](model-tool-probe.md)安全配置 `EASEL_PROBE_BASE_URL` 和 `EASEL_PROBE_API_KEY`：

```bash
python scripts/agent_task_eval.py --live --model YOUR_MODEL --samples 1 --total-timeout 180
```

每类默认 1 样本，可选 1–5 样本；每轮默认 256 个输出 token，可用 `--max-tokens` 设置 1–1024。
总计最多 `samples × 7` 次请求；批次时限默认 180 秒、最多 600 秒，每任务最多 60 秒且受剩余
总时限约束。HTTP/传输错误或超时停止后续任务，没有自动重试、重定向或模型替换。输入的费用
以及超时后的远端计算仍可能计费，这些限制不是货币预算。CI 只运行离线 HTTP fixture。

报告包含每任务的状态、请求/模拟工具次数、耗时、完整或未知的 token 用量，以及每场景的
已尝试数、未运行数、完成率和工具检查错误率。完成率以已尝试样本为分母，必须同时查看
`complete` 和 `not_run`，不能把中止批次当成全量结果。工具错误率以明确评分的工具决策为
分母（缺失/错误调用、参数/顺序错误以及禁止重试却重试）；无法解析的响应还需看任务状态，
不能只看这个错误率。工具本身返回预设 unknown 是测试条件，不是模型工具错误。

只报告聚合结果及地址/请求模型的部署指纹，不保存模型名、地址、密钥、提示、回执、原始响应或推理；模型配置与代码
版本须另行记录。token 来自提供商响应，任一已开始请求缺失用量则该任务用量为 `null`；
`cost` 保持 `null`；如需估算，可离线使用[版本化成本统计](agent-task-cost.md)，它不会改写原始用量报告。
退出码 0：全部计划任务通过；1：失败或未完成；2：配置错误。
这些固定任务的小样本通过率不能用于模型排名、统计显著性或生产 SLA 声明。
